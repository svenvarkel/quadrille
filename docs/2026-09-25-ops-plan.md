# Operations layer — Plan

*2026-09-25. Branch `feature/ops` (worktree `.claude/worktrees/ops`). Prerequisite for
[the MCP server](2026-09-25-mcp-spec.md).*

## Intent

> Tee 1 ära - see kood peab kindlasti olema väga korralik ja modulaarne. Mingit double
> koodi ei tohi olla. Samuti taga maksimaalne katvus automaattestidega.

Where "1" is: extract the CLI operations (`read`, `set`/`apply`, `find`, `sort`, `check`,
`sheets`, `save`) and their JSON construction out of `cli::open()` into reusable
functions, so that the MCP server can call the same code instead of copying it.

## Acceptance criteria

1. **No behaviour change.** Every existing CLI invocation produces the same stdout
   JSON, stderr text and exit status. All existing tests pass unmodified (tests may be
   *added* or *moved*, not weakened).
2. **One implementation per concept.** A1 column/cell parsing and formatting exist once
   (`src/a1.rs`); currently duplicated in `cli.rs` (`address`, `cell`, `range`),
   `workbook.rs` (`address`, `a1`), `sort.rs` (column letters in `parse_sort`) and
   `main.rs` (`column_name`, inline `format!("{}{}", column_name(c), row + 1)`).
   Workbook-specific rules (`$` stripping, 1,048,576 × 16,384 bounds, its error texts)
   stay in `workbook.rs` as a thin wrapper over `a1`. The `{cell, value}` patch-entry
   parser exists once and is usable by both `--apply` and a future MCP `set`.
3. **Operations are library API** in `src/ops.rs` (`quadrille::ops`), taking a
   `&mut Sheet` plus typed arguments and returning `serde_json::Value` (or typed data
   where JSON composition belongs to the caller). No argv, no stdout, no process exit
   inside `ops`.
4. **CLI is parse → validate → dispatch.** `cli.rs` holds argv parsing into a typed
   `Command` (pure function over an argument iterator, unit-testable in-process),
   the combination rules, and the call into `ops`; nothing else. The indexing-wait
   rule lives in one function.
5. **Coverage:** 100% line coverage of `a1.rs`, `ops.rs` and `cli.rs` except lines that
   require an I/O fault (listed with reason); no drop in any other file's line coverage.
6. `cargo test`, `clippy -D warnings`, `fmt --check`, the three Python smokes pass.

## Approach

1. `src/a1.rs`: `column_index` (moved from `lib.rs`), `column_name` (moved from
   `main.rs`), `parse_cell`, `cell_name`, `Range` + `parse_range` (with the read
   limits as parameters or a separate check in `ops`). Re-exported from `lib.rs`.
   Rewire `cli`, `workbook`, `sort`, `main` onto it.
2. Golden CLI test (step 1 of Verification) committed **before** touching `cli.rs`.
3. `src/ops.rs`: `sheets`, `check`, `wait_for_index`, `parse_edits` (from JSON
   `[{cell, value}]`), `apply_edits` → changes, `sort`, `read`, `find`, `save`,
   `describe` (source / sheet / format / workbook notes). Moved code, not rewritten logic.
4. `cli.rs`: `parse(args) -> Result<Command>`, `run(Command) -> Result<Option<Sheet>>`.
5. Tests, coverage pass, Codex diff review, fix.
6. Report to Sven; merge on his go-ahead.

Rollback: revert the branch merge; no data or format changes. Out of scope: `main.rs`
TUI split, MCP itself, any new CLI option.

## Plan review (Codex, 2026-09-25)

All five findings verified and accepted; they amend the criteria and approach above.

1. **Verification (high).** The golden matrix is exactly the CLI invocations already in
   `tests/cli.rs`, `tests/find.rs` and `workbook_smoke.py`, plus the rejection table.
   "Unmodified" means no existing assertion is removed or weakened; a test may move only
   if its code moves. Coverage is enforced, not eyeballed: `cargo llvm-cov --json` plus a
   small checker that fails if `a1.rs`, `ops.rs` or `cli.rs` drop below their target
   or any other file drops below its `develop` baseline (baseline numbers recorded in
   this plan before the refactor).
2. **Error texts differ (high).** Confirmed: CLI, workbook and sort parsers emit
   different messages. `a1` returns a structured error (`enum A1Error`); each caller
   maps it to its existing text, so messages stay byte-identical. `cli.rs` is bin-only:
   its in-process tests are binary unit tests, which `cargo llvm-cov` counts. No
   `preserve_order`, so JSON keys stay sorted regardless of composition order.
3. **More duplication (medium).** Also unify: the test-only `ready()` index-polling
   helpers (lib, sort, find, workbook tests) into one `#[cfg(test)]` helper; every
   inline `format!("{}{}", column_name(..), row + 1)` onto `a1::cell_name`; the
   repeated source/sheet/format JSON enrichment into one function. Checked by grep.
4. **Cut (medium).** No `describe`, no parameterised range policy (read limits stay
   fixed, in one place), no test moves for their own sake, no before/after table.
5. **Boundary (high).** `ops` functions take `&mut Sheet` (or a path for `sheets`) and
   return **typed results** (`ReadResult`, `Changes`, `FindOutput`, …). Each result
   type has one `to_json()` in `ops`, which CLI and MCP both call, so the JSON shape
   is defined once. The document registry (`doc_id` → `Sheet`) and JSON-RPC belong to
   the MCP server, not `ops`.
