## Acceptance criteria

1. `Sheet::find(query, from, limit)` returns matching cells in row-major view order with
   the values `--read` would return (edits applied, formula cells as cached results).
2. Substring, `exact`, `ignore_case` and column-filter modes behave as specified,
   including `--exact --find ''` matching existing empty fields only.
3. Paging: resuming with `next` as `from` yields exactly the remaining matches — no
   skips, no duplicates — including when the limit is hit in the middle of a record.
4. Find works before background indexing has finished and returns early once `limit` is reached.
5. With an active sort, find iterates the view order and reports view coordinates.
6. With `--set`/`--apply --dry-run`, find sees the edited values; edits beyond a record's
   length (XLSX virtual columns) are searched.
7. Source changes during the scan and invalid UTF-8 produce errors, not partial success.
8. CLI: every option in the spec parses; every invalid combination listed in the spec is
   rejected with a nonzero exit and a message on stderr; output JSON matches the spec.
9. CSV, XLSX and ODS all supported (workbook `--sheet` selects the searched sheet).
10. Existing behaviour unchanged: all current tests pass; `clippy -D warnings` and `fmt` clean.
11. Coverage: every line of `src/find.rs` and every new CLI branch is exercised by
    `cargo test`, measured with `cargo llvm-cov`. Any line left uncovered is listed with
    the reason in the final report.

## Approach

Order (TDD per step: failing test first, then code):

1. **`src/find.rs`** (new, `mod find;` + re-exports in `lib.rs`)
   - `pub struct FindQuery { text, columns: Option<Vec<usize>>, exact, ignore_case }`
   - `pub struct FindResult { matches: Vec<((u64, usize), String)>, next: Option<(u64, usize)>, records_scanned: u64 }`
   - `impl Sheet { pub fn find(&self, query: &FindQuery, from: (u64, usize), limit: usize) -> Result<FindResult> }`
   - `&self`: opens its own `csv::Reader` on `data_path()` so it neither disturbs the
     viewport reader nor waits for the index. Unsorted: seek via the sparse index when the
     start row's stride is already indexed, else parse forward from byte 0. Sorted:
     iterate `order.rows[from..]`, seeking each `RecordRef`.
   - Per record: iterate present fields plus edited columns past the record length
     (`edits.range((row,0)..=(row,MAX))`), apply column filter, get value via existing
     `value()` logic on source row, match.
   - `check_source()` before and after the scan.
   - Needs `pub(crate)` access to `edits`, `order`, `index` (same crate; `sort.rs` already
     does this).
2. **CLI (`src/cli.rs`)**: parse `--find`, `--exact`, `--ignore-case`, `--columns`, `--from`,
   `--limit`; validation per spec; reuse `address()` for `--from`, a `column()` helper
   for `--columns`; skip the indexing wait for find-only calls; emit JSON. Update `HELP`.
3. **Tests**: unit tests in `src/find.rs`; CLI tests in `tests/cli.rs`; workbook tests in
   new `tests/find.rs` (move `column_name` usage untouched).
4. **Docs**: README "Agent CLI" section gets a Find subsection; limitations list updated.
5. **Coverage pass**: `cargo llvm-cov`; add tests for uncovered branches.
6. Codex diff review (`codex exec review --base develop` + follow-up questions), fix, re-check.
7. Merge `feature/find` into `develop` (no rebase), push, remove worktree.

Rollback: purely additive — one new module, new CLI options, no format or on-disk changes.
Revert the merge commit on `develop`.

Dependencies: none added. `cargo-llvm-cov` is a local dev tool only.

## Plan review (Codex, 2026-09-25)

Round 1, 15 findings. Verified against the code; the spec was updated accordingly
(spec is not the Intent). Acceptance criteria above stand, amended as noted here.

Accepted:

1. **AC4 vs AC7 conflict (high).** Early exit cannot validate the rest of the file.
   *Amends AC7:* only the scanned part is validated; invalid UTF-8 after an early exit
   is not detected (same contract as `--read`). Test: invalid UTF-8 *before* the limit
   is reached errors; invalid UTF-8 after an early exit does not.
2. **`next` at EOF (high).** No read-ahead: `next` is non-null whenever the limit was
   hit, so the last page may be empty. Tests: final cell, ragged rows, filtered columns,
   XLSX edit at XFD.
3. **Workbook rectangle (high).** Confirmed: `workbook.rs` writes a dense CSV rectangle
   up to the last used row/column. Spec now uses dense-rectangle semantics for
   workbooks; `--exact --find ''` matches blanks inside the rectangle.
4. **Concurrency proof (high).** The start-position choice is factored into a function
   over an offsets snapshot (published stride → seek; unpublished → parse from byte 0)
   and unit-tested deterministically, plus a multiline-quoted record straddling a stride.
5. **Mid-scan source change (high).** A `#[cfg(test)]`-reachable per-record hook in the
   inner scan function lets a test mutate the source after scanning begins; asserts an
   error. Workbook archive mutation (touch the `.xlsx`) tested too.
6. **Paging combinations (medium).** Property-style test: concatenated pages for every
   limit 1..=N equal the full result, repeated over column filters, ragged records,
   empty fields, sorted view, edits and workbook blanks; `from` column past the last
   filtered column resumes on the next row.
7. **Formula cases (medium).** Tests: cached present, cached absent (empty value),
   stale cached value after editing an input, new `=...` overlay text.
8. **`records_scanned` (medium).** Defined as records read by this call.
9. **`--columns` validation (medium).** Strict parsing specified; errors on empty items,
   whitespace, non-letters, beyond XFD.
10. **Duplicate column parsing (medium).** One crate-level `column_index(letters)` in
    `lib.rs`, used by CLI `address()` and `--columns`. Workbook/sort parsers stay as
    they are (different inputs, out of scope).
12. **Rollback (medium).** Revert scope: `src/find.rs`, `lib.rs` exports and
    `column_index`, `cli.rs` options/help/wait logic, README section, tests, docs. After
    revert: `cargo test`, Python smokes, `qd x.csv --find a` must fail with
    "Unknown option".
13. **Merge/push (medium).** Cut from this plan. Step 7 becomes: report to Sven; merge
    `feature/find` into `develop` and push only on his go-ahead.
14. **ignore-case wording (low).** Spec/help say "Unicode lowercase, not case folding".
15. **Coordinate system (low).** Output adds `"coordinates": "source" | "sorted_view"`.

Rejected:

11. **Reuse `workbook_smoke.py` fixtures instead of Rust fixtures.** Coverage is measured
    with `cargo llvm-cov`, which only sees code driven by `cargo test`. Workbook find
    tests are Rust tests building minimal XLSX/ODS packages with the already-present
    `zip` crate. `workbook_smoke.py` gets one `--find` assertion as an end-to-end check.
