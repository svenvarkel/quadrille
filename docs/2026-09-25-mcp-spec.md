# MCP Server — Specification (draft)

*2026-09-25. Status: draft, not reviewed. Depends on find ([2026-09-25-find-spec.md](2026-09-25-find-spec.md)).*

## Problem

Every CLI call re-opens and re-scans the file (about 1.7 s for 1.28 GB), and edits
live only for one process, so they must be batched into a single `--apply`. An agent
needs a long-lived session: open once, then read, find, edit, undo and save in small steps.

## Scope

In scope: `qd --mcp`, an MCP server over stdio (JSON-RPC 2.0, newline-delimited),
exposing the existing engine. No new engine features beyond find.

Out of scope: HTTP transport, sharing a live session with the TUI (`qd --serve`),
authentication, a remote/hosted server.

## Tools

| Tool | Arguments | Result |
| --- | --- | --- |
| `open` | `path` (absolute), `sheet?`, `delimiter?` | `doc_id`, `format`, `sheets`, `records`, `indexing` |
| `info` | `doc_id` | sheets, dirty edit count, indexing progress, sort, source stamp status |
| `read` | `doc_id`, `range` | same JSON as CLI `--read`, including `formulas` |
| `find` | `doc_id`, `text`, `columns?`, `exact?`, `ignore_case?`, `from?`, `limit?` | same JSON as CLI `--find` |
| `set` | `doc_id`, `edits[{cell, value}]`, `dry_run?` | changed cells with `before` / `after` |
| `undo` | `doc_id`, `count?` | number of edits undone |
| `sort` | `doc_id`, `spec`, `header?` (`spec: "clear"` restores source order) | new view summary |
| `save` | `doc_id`, `path?` | output path; same no-clobber / atomic source-replace rules |
| `close` | `doc_id` | — |

Coordinate rules, limits (100,000 cells / 10,000 records per read, 10,000 find matches)
and error texts are the CLI's. The server is a thin transport over the same engine.

## Installation

```sh
cargo install --path .        # from the repository; installs ~/.cargo/bin/qd
cargo install quadrille       # once published to crates.io
```

Homebrew tap and prebuilt GitHub release binaries are possible later, so that users
do not need a Rust toolchain.

## Registration

The client starts `qd --mcp` as a subprocess and talks to it over stdin/stdout.
Always use the absolute binary path: GUI applications do not inherit the shell's `PATH`.

**Claude Desktop:** `~/Library/Application Support/Claude/claude_desktop_config.json`
(Windows: `%APPDATA%\Claude\claude_desktop_config.json`), then restart Claude Desktop.

```json
{
  "mcpServers": {
    "quadrille": { "command": "/Users/<user>/.cargo/bin/qd", "args": ["--mcp"] }
  }
}
```

For distribution, a `.mcpb` bundle (Claude Desktop Extension) allows one-click installation.

**Claude Code:**

```sh
claude mcp add quadrille -- qd --mcp
```

**Codex:** `~/.codex/config.toml`

```toml
[mcp_servers.quadrille]
command = "/Users/<user>/.cargo/bin/qd"
args = ["--mcp"]
```

**ChatGPT Desktop:** unverified. The last known state is that ChatGPT supports MCP only
as remote connectors (developer mode, HTTPS URL), not local stdio processes. Check the
current state before relying on this. If it still holds, ChatGPT needs an HTTP
transport (`qd --serve`, also required for the shared TUI session) or a stdio-to-HTTP
bridge. Tunnelling local files to the public internet is not an acceptable default.

## Security

The server runs with the user's permissions and can read any file the user can.
`open` requires absolute paths; saves follow the CLI's no-clobber rules (only the source
itself may be atomically replaced). No network listener in this version.

## Open questions

- Multiple open documents per server, or one? (Draft: several, keyed by `doc_id`.)
- Hand-rolled JSON-RPC over `serde_json` (~200 lines) versus the `rmcp` SDK. Draft:
  hand-rolled until HTTP or streaming is needed.
- Long operations (no-match find on a large file, sort, save) block the call; progress
  notifications are a later addition.
